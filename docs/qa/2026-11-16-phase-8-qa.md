## 2. 60k-point GeoJSON import: main-thread blocking
**FAIL against the Review Focus target (< 250 ms).** 7.88 MB, 60,000 points, imported with a single layer in the project (to avoid accumulation).
- Dev server: long tasks `[start ms after trigger, duration ms]` = `[1687, 2237]` (plus a 195 ms task before the trigger). Layer toast at about 3.0 s.
- Production build (`vite preview`): one long task `[2542, 1562]`; toast at 3.3 s.
- A first-run dev measurement showed a 429 ms task at t=0 only.
- Interpretation: the parse itself is off-thread (the overlay shows, and the import is cancellable), but a single 1.5-2.2 s main-thread task occurs near the end of the import (layer commit and render of 60k points). Baseline before the phase was reported as about 970 ms by a rAF gap, which is not comparable with this longtask measure, so no improvement or regression can be claimed. Importing 60k points repeatedly into one project made a later import block for 3.8 s (accumulated layers, dev server).

## Bugs found
1. (Performance) Importing a 60k-point GeoJSON blocks the main thread for 1.56 s (production build) / 2.24 s (dev) in one task near the end of the import, vs the < 250 ms Review Focus target (section 2). Not fixed (QA only).
2. (Medium, accessibility) Select By Attributes and Select By Location do not move focus into the dialog on open, so the Tab trap is inactive until the first Tab; Map Properties does move focus in, and the branch states focus is trapped in all modal dialogs. Reproduction: Map tab; focus the `By attributes` (or `By location`) button and activate it; read `document.activeElement` -> it is still the ribbon button (`BUTTON By attributes` / `BUTTON By location`) and is outside `[role=dialog]`. Same sequence with `Properties` leaves focus on an INPUT inside the dialog. Tab wrap, Escape and focus restore work once focus is inside.
3. (Performance) Geoprocessing in the worker still has a main-thread cost: Buffer with Dissolve all on 60,000 points showed three long tasks of 334, 290 and 316 ms (starts 81058, 81781, 82761 ms; Run clicked at 81058) before the cancel took effect, each above the 250 ms stall target. Likely candidates (not investigated): input serialisation to the worker, result deserialisation, or layer rendering. Reproduction: import a 60k-point GeoJSON, Analysis > Buffer, 500 m, Dissolve all, Run; observe with a `PerformanceObserver({entryTypes:['longtask']})`.
(Observations, not defects: View-tab workspace presets also switch the ribbon tab; Clear session keeps the project name - judged expected, see section 9.)
